# 要件定義: 地域ページにログインなしの体験版（ISBN 1件の予約可否チェック）を置く（#183）

親Issue: #181

## Problem Statement

#182 で地域ページ（`/library/add/{都道府県}/{市区町村}`）は「この地域の図書館に対応している」ことを伝えられるようになったが、その場でアプリの価値（本のバーコードで、図書館で借りられるか・予約できるかが分かる）を試す手段がない。試すにはログインし、図書館を登録してからスキャンする必要があり、検索流入から価値到達までの距離が長い。

一方で、カーリル `check` API には利用上限があり、#159 では「未ログインでの蔵書状況表示」を次の理由で却下している。

- `check` は「各アプリケーションキーにつき、IP毎に、1000書籍リクエスト/時」（書籍リクエスト = ISBN 1件 × 図書館システム 1件）。出典: [図書館API仕様書](https://calil.jp/doc/api_ref.html)
- 本アプリは `check` をサーバ（Pages Functions）経由で呼ぶため、上流から見た IP は Cloudflare のものになり、**全ユーザーで上限を共有している**とみなす必要がある
- 未ログインに無制限で開放すると、乱用で上限に達し、ログインユーザーの検索まで止まる（#89 で認証必須にした経緯）

本Issueは、この懸念に対する設計上の答え（体験版の消費に上限を設け、ログインユーザーの枠を守る）を示したうえで体験版を実装する。

## 調査結果（実現可否の判断材料）

| 項目 | 確認結果 | 出典 |
|---|---|---|
| 利用規約 | 自社のサイト・アプリで図書館の蔵書情報を提供する用途なら利用可。appkey を第三者に貸与・譲渡することは禁止（本設計はサーバ内でのみ使うため該当しない）。仕様書は予告なく変更されうる | [利用規約](https://calil.jp/doc/api_license.html) |
| クレジット表示 | 「APIを使って取得された図書館名または『蔵書あり』『貸出可』などの貸出状況を表示するときは、かならずカーリルのページに対してリンクを貼らなければなりません」 | [仕様書](https://calil.jp/doc/api_ref.html) |
| 利用上限 | `check`: appkey × IP ごとに 1000書籍リクエスト/時。1セッションの最大は100書籍リクエスト。ポーリングは書籍リクエストを消費しない | 同上 |
| ポーリング | 2秒以上の間隔。`continue` が 0 になるまで繰り返す | 同上 |
| 費用 | 法人・個人を問わず無償 | [図書館API](https://calil.jp/doc/api.html) |
| Cloudflare の Rate Limiting binding | Pages Functions では使えない（Workers 専用。拠点ごとの概算カウント） | [Pages Functions bindings](https://developers.cloudflare.com/pages/functions/bindings/) |

**結論: 実現可能。** クレジット表示は「図書館名をカーリルの図書館ページへのリンクにする」既存の方式（#156）で満たせる。利用上限は、D1 で体験版専用の消費枠を管理することで、ログインユーザーの枠を守れる。

## Requirements

### Functional

- **F1. 入口**: 市区町村ページ（`/library/add/:pref/:city`）に、ISBN を1件入力する欄と「この地域の図書館で調べる」ボタンを置く。既存の「図書館を選択して登録する」一覧はその下に残す。
- **F2. ログイン不要**: 未ログインでも使える。ログイン済みでも使える（同じ体験版）。
- **F3. 対象**: 調べる図書館は、そのページの市区町村の図書館に限る。クライアントは図書館システムを指定できない（サーバが静的データから決める）。
- **F4. 結果表示**: 本のタイトル（OpenBD、取得できれば）と、市区町村の各図書館の貸出状況（蔵書あり／貸出可／貸出中／蔵書なし等）、予約可能な場合は予約ページへのリンクを表示する。図書館名はカーリルの図書館ページへのリンクにする（クレジット表示）。
- **F5. 登録への誘導**: 結果の下に「この地域の図書館を登録すると、バーコードを読み取るだけで毎回調べられます」と、下の登録一覧への導線を置く。
- **F6. 乱用対策**:
  - 体験版全体の消費上限（1時間あたりの書籍リクエスト数）。上限に達したら体験版だけを止め、ログインユーザーの検索には影響させない
  - 接続元ごとの上限（1時間あたりの体験回数）
  - 同じ ISBN × 同じ市区町村の結果は短時間キャッシュし、上限を消費しない
  - ISBN の形式（10桁／13桁・チェックディジット）をサーバで検証する
- **F7. 上限到達時の表示**: 「体験版は混み合っています。ログインして図書館を登録すると制限なく調べられます」と案内し、ログイン導線を出す（エラー扱いにしない）。
- **F8. 計測**: 体験版の実行・結果表示を GA4 イベントで計測し、登録への到達（#169 の既存イベント）と合わせて評価できるようにする。
- **F9. プライバシーポリシー**: 「利用には Google アカウントでのログインが必要」の記述を改め、体験版の乱用対策で接続元 IP のハッシュ値を短期間（2時間以内）保存することを記載する。

### Non-Functional

- **NF1. ログインユーザーの保護**: 体験版がどれだけ使われても、体験版の消費は設定した上限を超えない。
- **NF2. 応答時間**: 体験版の1回の問い合わせは、カーリルのポーリング完了まで最長約20秒。待ち時間中は進捗を表示する。
- **NF3. セキュリティ**: appkey はサーバ内でのみ使う。保存する IP はシークレット付きのハッシュのみで、生の IP は保存しない。
- **NF4. JS 非実行の HTML**: 入口（見出し・説明・入力欄）は配信 HTML に含める（#182 の方式）。結果の表示は JS で行う。
- **NF5. 文言**: キーワードで蔵書検索できるように読める表現は使わない。ISBN（本のバーコード）での確認であることを明示する。

## Constraints

- 既存の URL（`/library/add/...`）は変更しない。
- 既存の `/api/calil/*`（ログイン必須）は変更しない。体験版は別エンドポイントにする。
- 既存のログイン後の図書館登録フローを壊さない。
- 永続化は既存の D1 を使う（新しいマイグレーションを追加）。

## Acceptance Criteria

- **AC1**: 未ログインで野洲市・可児市のページを開き、ISBN を1件入力すると、その市区町村の各図書館の貸出状況が表示される（ブラウザ・コールドロードで確認）。
- **AC2**: 図書館名がカーリルの図書館ページへのリンクになっている。
- **AC3**: 接続元ごとの上限を超えると 429 が返り、画面に F7 の案内が出る。
- **AC4**: 体験版全体の上限を超えると 429 が返り、その間もログインユーザーの `/api/calil/check` は動く（体験版の消費が独立していることをテストで確認）。
- **AC5**: 同じ ISBN・同じ市区町村の2回目はキャッシュから返り、カーリルを呼ばない（上限も消費しない）。
- **AC6**: 不正な ISBN・存在しない市区町村・図書館システム数が多すぎる市区町村は 400 で、カーリルを呼ばない。
- **AC7**: 配信 HTML（JS 非実行）に体験版の見出し・説明・入力欄が含まれる。
- **AC8**: 既存の登録フロー（選択 → 登録、未ログイン時のその場ログイン）が従来どおり動く。
- **AC9**: プライバシーポリシーが更新されている。
- **AC10**: `npm test`・`npx tsc -b`・`npm run build` が通る。

## User Stories

- 本屋で見つけた本を地元の図書館で借りられるか知りたい人として、ログインせずにその場で1冊だけ試したい。
- 試して便利だと分かった人として、そのまま地元の図書館を登録したい。
- ログインして日常的に使っている人として、体験版が混雑しても自分の検索が止まらないでほしい。
- 運営者として、カーリルの規約と利用上限を守りながら、検索流入を価値到達につなげたい。
