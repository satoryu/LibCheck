# Requirements — #158 地域（自治体×図書館）ページを認証なしで公開する

## Problem Statement

親Issue #155（[Epic] SEO改善）の本命施策。現状 Google にインデックスされうるのはトップページ1枚のみで、一般語（「図書館 蔵書 検索」等）ではカーリル本体・各自治体OPACと競合し勝ち目が薄い。一方「〈自治体名〉 図書館」のような地域名クエリは、(a) ページ数が数千と現実的、(b) 図書館名という実データがあり内容が薄くならない、(c) データが準静的で静的化できる、という条件が揃っている。

図書館を選ぶ画面（都道府県選択・市区町村選択・図書館一覧）は既に存在するが、認証必須のため未ログインでは閲覧できずインデックスされない。加えて図書館一覧はカーリル `library` API をランタイムで呼んでいる。

## 事前の設計判断（ユーザー確認済み・2026-08）

地域データ（都道府県×市区町村×図書館一覧）の静的化・更新方式について、3案（① 手動スクリプト・随時更新、② GitHub Actions に新規シークレットを追加し毎デプロイ自動生成、③ D1 + 内部再生成エンドポイント）を比較検討し、**① 手動スクリプト・随時更新**を採用した。

理由:
- コスト・実装・リスクいずれも最小（新規シークレット不要・CI変更なし・キーの複製なし）
- カーリル自身が `/library` を「準静的」と説明しており、頻繁な自動更新は不要
- `scripts/` に生成スクリプトを1本追加し、必要なタイミング（例: 年数回）で開発者が手元の `.env.local` の `CALIL_APP_KEY` を使って再実行し、生成された静的JSONを通常のPRとしてコミットする運用

比較の詳細は本ドキュメント末尾を参照。

## Requirements

### Functional

- 以下3ルートを未ログインで閲覧できること。図書館の**登録操作のみ**ログインを要求すること。
  - `/library/add`（都道府県選択）
  - `/library/add/:pref`（市区町村選択）
  - `/library/add/:pref/:city`（図書館一覧）
- 図書館一覧・市区町村一覧は、閲覧時にカーリル API を呼ばず、ビルド時に生成した静的JSONから表示すること。
- 各ページに固有の title / description / canonical を出すこと（#157 の仕組みを利用）。
- `noindex` を外し、検索エンジンにインデックスされるようにすること（#157 では全ルートに `noindex` を付けていたが、公開する3ルートは除外する）。
- `public/sitemap.xml` に都道府県ページ・市区町村ページを追加すること（静的生成、生成スクリプトが兼務）。
- 未ログインで図書館の登録を試みた場合、ログインへの導線を示すこと（サイレントな 401 失敗にしない）。
- カーリルへのリンクバックが表示されること（#156 で実装済みのものが、認証状態に関わらず機能することを確認する）。

### Non-Functional

- 静的化により、これら3ルートの閲覧がカーリルの利用制限（1000リクエスト/時）を一切消費しないこと。
- 生成データは `Library` ドメインモデルと同じ形（camelCase）で保存し、既存の型・ロジックと自然に接続できること。
- 生成スクリプトはカーリルへの配慮として、47都道府県へのリクエスト間に適切な間隔を空けること。
- 生成スクリプトの実行ログに `CALIL_APP_KEY` の値を一切出力しないこと。

### データ静的化方式の比較（採用: ①）

| 案 | コスト | 実装 | リスク | 運用 |
|---|---|---|---|---|
| **① 手動スクリプト・随時更新（採用）** | 低（新規シークレット不要） | 低（生成スクリプト1本） | 低（キー複製なし） | 手動再実行（例: 年数回） |
| ② GitHub Actions 新規シークレット・毎デプロイ自動生成 | 中（シークレット追加操作） | 中（CIワークフロー変更） | 中（キーが2箇所に存在） | 完全自動 |
| ③ D1 + 内部再生成エンドポイント | 高（新規シークレット1つ・D1設計） | 高（新規エンドポイント・マイグレーション・CI連携） | 低〜中（キー複製なし、攻撃対象面は増える） | 完全自動 |

Cloudflare Pages Functions は cron/スケジュール実行に対応していない（Workers 固有機能。公式ドキュメント・コミュニティで確認済み）ため、②③はいずれも「デプロイ後に外部からトリガーする」形になり、①に対する運用上の優位性が薄い。

## Constraints

- Calil `/library` API の直接呼び出しはビルド前提のスクリプトからのみ行う（クライアント・本番ランタイムからは呼ばない）。
- 生成される都道府県別 JSON のファイル名は、既存ルーティング（`/library/add/:pref` が日本語の都道府県名をそのまま使う）との整合のため、日本語の都道府県名をそのまま使う（例: `public/data/libraries/東京都.json`）。
- `functions/_shared/routeMeta.js` は `/library/add` 系のエントリを「非公開・noindex」から「公開・固有メタ情報」に更新する必要がある（#157 で作った仕組みの利用）。
- `src/presentation/auth/publicPaths.ts` の `PUBLIC_PATHS` に該当パスパターンを追加する必要がある（#157 で用意した拡張ポイント）。

## Acceptance Criteria

- [ ] 未ログインで3ルート（都道府県選択・市区町村選択・図書館一覧）が閲覧できる
- [ ] 各ページに固有の title / description / canonical が出る（`curl` で確認）
- [ ] 上記3ルートが `noindex` ではなくなっている
- [ ] 図書館一覧が静的データから表示され、閲覧時にカーリル API を呼ばない（ネットワークタブ / Function ログで確認）
- [ ] `sitemap.xml` に都道府県ページ・市区町村ページが含まれる
- [ ] 図書館の登録操作は従来どおりログインが必要。未ログインで登録を試みるとログインへの導線が示される
- [ ] カーリルへのリンクバックが表示されている（#156、認証状態に関わらず）
- [ ] 既存のテスト・型チェックが通る
- [ ] （マージ後）Search Console で地域ページのインデックス登録を確認する

## User Stories

- 検索エンジン経由でやってきた利用者として、自分の街の図書館が LibCheck に登録されているか、ログインせずにまず確認したい。
- 確認できたら、その場でログインして図書館を登録し、蔵書検索を使い始めたい。
- LibCheck の開発者として、地域ページの公開によってカーリルの API クォータを消費したくない。
