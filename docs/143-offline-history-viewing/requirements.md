# #143 オフライン時に登録図書館・検索履歴を閲覧できるようにする（レベル2）— Requirements

## Problem Statement
電波の悪い場所やオフライン時、登録図書館・検索履歴の GET が失敗し、エラー画面になってしまう。
これらは個人データで更新頻度も低いため、「最後に取得した状態」をオフラインでも見られれば十分価値がある。
一方 Calil の蔵書状況はリアルタイム性が命で、古い結果を見せるのはむしろ有害なので対象外とする。

## Requirements
- FR-1: `GET /api/registered-libraries` のレスポンスをオフラインでも「最後に取得した状態」で閲覧できる
- FR-2: `GET /api/search-history` のレスポンスをオフラインでも「最後に取得した状態」で閲覧できる
- FR-3: `GET /api/calil/*`（蔵書状況）はキャッシュ対象に含めない（常にネットワーク）
- FR-4: オフラインでキャッシュ閲覧中であることがユーザーに分かるインジケーターを表示する
- FR-5: ログアウト時にオフラインキャッシュを削除し、同一端末で次にログインする別ユーザーへ前ユーザーのデータが残存しないようにする
- NFR-1: 既存の D1 スキーマ・API 実装は変更しない（クライアント側のキャッシュ戦略のみで実現する）
- NFR-2: Workbox の Cache Storage（ブラウザの HTTP キャッシュとは別レイヤー）を使う。functions 側が付与する `Cache-Control: no-store` はこの層に影響しないため、その関係をコード上に明記する

## Constraints
- 既存の `useOnlineStatus` フック・オフラインバナー（#145）を再利用する
- 認証は HttpOnly セッション Cookie（#91）。Cache Storage のキーは URL 単位でユーザー識別を含まないため、
  ログアウトで明示的にキャッシュを消さない限りブラウザ内に前ユーザーのデータが残り得る

## Acceptance Criteria
- AC-1: オフライン時に登録図書館一覧・検索履歴一覧がエラーにならず、最後に取得した内容を表示する
- AC-2: オフライン時に Calil（蔵書状況）はキャッシュされず、通常どおりエラーとして扱われる
- AC-3: 図書館・履歴タブのオフラインバナーに「表示中のデータは前回取得時点のものです」等、キャッシュ閲覧である旨が表示される
- AC-4: ログアウト後、該当キャッシュ（Cache Storage）が削除されている
- AC-5: `npx tsc -b` / `npm test` 緑（TDD）
- AC-6: 本番で `npm run build` の生成物（`dist/sw.js`）と実際のキャッシュ挙動を確認する

## User Stories
- 電波の悪い場所で本アプリを開いたとき、いつも使っている図書館の一覧が見られず困っていた。
  オフラインでも前回見た一覧が出れば、蔵書検索に必要な情報（どの図書館を見るか）の判断はできる。
- 図書館で検索履歴を見返したいが、その場でネットワークが不安定だった。
  最後に検索した本の一覧だけでも見えれば十分役に立つ。
