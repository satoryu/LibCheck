# Requirements — #156 カーリルAPI規約: リンクバックの実装

## Problem Statement

LibCheck は [カーリル 図書館API](https://calil.jp/doc/api_ref.html)（無償提供）を利用して図書館名と貸出状況を表示しているが、API 仕様書が定めるカーリルへのリンクバック義務を満たしていない。

仕様書の原文（2026-08 時点、`https://calil.jp/doc/api_ref.html` の「カーリルへのリンク」節）:

> APIを使って取得された図書館名または「蔵書あり」「貸出可」などの貸出状況を表示するときは、かならずカーリルのページに対してリンクを貼らなければなりません。カーリルAPIを使って得た情報からカーリルへリンクする方法を説明します。

LibCheck は図書館名・貸出状況の**両方**を表示しているため明確に対象である。現状 UI にカーリルへのリンクは1つも存在しない（`grep -rn "calil.jp" src/ | grep -v api.calil` がヒットなし）。

これは SEO 施策（#155）とは独立した、**本番稼働中のアプリが抱える規約違反**である。加えて、LibCheck の中核機能はカーリルの `appkey` に全面的に依存しており、規約違反を理由にキーが停止されればアプリの主要機能が停止する。運用上の単一障害点でもある。

## 仕様書が定めるリンク形式

| 対象 | URL 形式 |
|---|---|
| 個別の本ページ | `https://calil.jp/book/{ISBN10}` |
| 図書館ページ | `https://calil.jp/library/{libid}/{図書館の正式名称}` |
| 図書館ページ2（libkey とシステムIDから飛ぶ場合） | `https://calil.jp/library/search?s={システムID}&k={図書館のLibkey}` |

※ 仕様書上、図書館ページは `https://calil.jp/library/{図書館の正式名称}` から `https://calil.jp/library/{libid}/{図書館の正式名称}` へ更新されたことが `-->` で示されている。**新しい方（libid を含む形式）を使う。**

※ リンクテキスト・ロゴ・帰属表記の文言についての指定は無い。リンクの粒度（書籍ごと／図書館ごと／ページに1つ）も明示されていない。

## Requirements

### Functional

- 図書館名または貸出状況を表示するすべての画面から、カーリルの該当ページへのリンクを辿れること。
- リンク先 URL は仕様書が定める形式に一致すること。
- 対象画面:
  - 検索結果画面（`/result/:isbn`）— 図書館名・貸出状況の両方を表示
  - 検索履歴画面（`/history`）— 貸出状況（過去の検索結果のスナップショット）を表示
- リンクは外部サイトへの遷移であることが利用者に分かる表現であること。

### Non-Functional

- 既存の画面レイアウトを大きく崩さないこと。特に履歴画面は #153 で横スクロール問題を修正したばかりであり、行内の要素を増やしてレイアウト幅を圧迫しないこと。
- ISBN10 が導出できない ISBN（979 で始まるもの）でも表示が壊れないこと。
- 図書館データの一部フィールドが欠けていてもリンクが破綻しないこと。

## Constraints

- リンクは `<a href>` による外部遷移であり、現行の CSP（`public/_headers`）は外部リンクの遷移を制限しないため CSP の変更は不要。
- `isbnValidator.isbn13to10()`（`src/domain/utils/isbnValidator.ts`）は 979 始まりの ISBN に対して `null` を返す。ISBN10 を必要とする書籍ページリンクはこの場合に生成できない。
- 検証のために calil.jp へ過度なリクエストを送らないこと（本 Issue の趣旨に反するため）。実際、形式検証中にボット保護（403「ひとやすみしませんか？」）に到達している。

## Acceptance Criteria

- [ ] 検索結果画面から、書籍のカーリルページへのリンクを辿れる（ISBN10 が導出できる場合）
- [ ] 検索結果画面の各図書館から、その図書館のカーリルページへのリンクを辿れる
- [ ] 検索履歴画面からカーリルへのリンクを辿れる
- [ ] 生成される URL が仕様書の形式に一致している（ユニットテストで検証）
- [ ] 979 始まりの ISBN でも画面が壊れず、かつ貸出状況を表示する画面には必ずカーリルへのリンクが存在する
- [ ] 既存のテスト・型チェックが通る
- [ ] 本番でリンクが実際にカーリルの正しいページへ遷移することを確認する

## User Stories

- カーリル（API 提供者）として、自分たちのデータを利用するアプリから正しく自サイトへ送客されてほしい。
- LibCheck の利用者として、蔵書情報の出所が分かり、より詳しい情報をカーリルで確認できるようにしたい。
- LibCheck の開発者として、依存している無償 API の規約を遵守し、キー停止による機能停止リスクを排除したい。
